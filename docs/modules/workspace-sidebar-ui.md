# Сайдбар и окно

Локальный интерфейс слева от ChatGPT: выбор проекта с поиском, дерево выбранного проекта, сессии и исполнители, план, индикаторы работы, Settings и оформление. [Сессии](workspace-sessions.md), [план](plan-view.md), [доставка](context-delivery.md), [DOM цветов](chatgpt-dom-compatibility.md).

## Код

- `src/ui/index.html` — разметка и CSS сайдбара (токены `--tree-*`, светлая/тёмная тема), `<dialog id="rename-dialog">`, splitter.
- `src/ui/sidebar.mjs` — меню проектов, дерево выбранного родителя, меню сессий, переименование, splitter, часы и адресные уведомления.
- `src/ui/progress.mjs` — `operationLabel`, `createProgress` (сайдбар и окно архива).
- `src/ui/settings-panel.mjs` — `settingsPanelView`: тема, вызовы инструментов, канал ChatGPT, «Цвета чата…», «Архив…», Доктор и восстановление потерянных исполнителей. Действия архива идут только каналами `archive:*` окна архива (`assertArchiveSender`); очистка одной orphan-записи идёт через отдельный `pilot:clear-orphan-executor` со строгой проверкой `assertLocalSender`.
- `src/preload.cjs` — `window.webPilot` (узкие методы, по одному IPC `pilot:*`); IPC принимается только от mainFrame сайдбара с его file-URL (`assertLocalSender`, иначе `IPC_FORBIDDEN`).
- `src/chat-colors-window.mjs` (`ChatColorsWindow.open/close/publish`), `src/chat-colors-preload.cjs`, `src/ui/chat-colors.{html,mjs}` — редактор цветов; `src/chatgpt-colors.mjs` — `ChatColors.set/apply/dispose`, `normalizeChatColors`, `validateColorChange`, `DEFAULT_COLORS`.
- `src/main.mjs` — `BaseWindow`, `layout`, `clampedSidebarWidth`, `saveSettings`, `applyShellTheme`, обработчики `pilot:set-sidebar-width|set-theme|copy-workspace-path|copy-external-client-line|open-chat-colors`.

Карточка плана содержит независимые «Включить/Выключить автовыполнение» и «Включить/Выключить Review»: зелёные при ON, `aria-pressed` в обеих темах. Review вызывает `pilot:plan-review`. Индикатор работы/успеха/внимания декоративный, статус текстовый (`role=status`); ожидание статично, reduced motion убирает анимацию. [Review](plan-review.md).

Блок «Связь с ChatGPT» показывается по активному ConversationRecovery, не по STALL_WARNING. «Перезагрузить страницу чата» видна только при canRetry; причина и пояснение говорят о той же странице без нового чата и повторного Send. Обработчик — `pilot:reconnect`, защиты — [context-delivery](context-delivery.md).

## Дерево «Ваши проекты»

Parallel-план добавляет под основным проектом группу «Исполнители» с названием сессии происхождения. Строки показывают задачу, worktree, Chat/Work, текстовое состояние и отдельные часы работы/ожидания; клик открывает собственную страницу без остановки остальных. Основной чат показывает общий план и пять проверяемых этапов: **Источник**, **Общий main**, **Диагностика**, **Финальное поручение**, **Итоговый ответ**, с текстовыми статусами и безопасным следующим действием. Writer блокирует main, но не источник и read-only диагностику; готовый source/URL исполнителя не означает проверенный main. UNKNOWN не скрывается, завершённый ответ не означает пользовательской приёмки. Этапы и причины отображаются в штатной карточке при 312 px без горизонтального переполнения, в обеих темах, с `aria-label` списка, `role=status`, текстом вместо одного цвета, клавиатурой и обычным фокусом переключателей. У исполнителя только своя задача и состояние; общий план и кнопки управления скрыты. AutoPlan проекта управляет исправлением и финалом без новой кнопки — [parallel-execution](parallel-execution.md).

Settings содержит разрешение параллельности (OFF) и положительный лимит (2). Они применяются к снимку новых основных сессий; сохранённые планы не перенастраиваются. Автоматическая передача исправления учитывает разрешение AutoPlan, готовность основного чата и завершение сверки. Статусы имеют текстовые подписи в обеих темах; время обновляется без функционального опроса.

- Меню «Ваши проекты» содержит поиск по имени/пути, список основных проектов, фоновые состояния «Работает»/«Требует внимания», создание, открытие папки и архив. ↑/↓ переводят фокус между доступными результатами, Enter выбирает, Escape закрывает; текущий проект обозначен. Фоновые страницы и их cwd при выборе не меняются.
- Ниже меню дерево только выбранного основного проекта с его сессиями и группой исполнителей. Выбор проекта возвращает последнюю выбранную активную сессию, с безопасным fallback на доступную; выбор исполнителя сохраняет дерево его родителя. Chevron сворачивает только это дерево.
- Меню проекта: «Новый Chat», «Новый Work», разделитель, «Переименовать», «Скопировать полный путь», «Скопировать строку для внешнего клиента», «Перенести в архив». Меню сессии: «Переименовать», «Перенести в архив». В дереве других кнопок создания сессий нет; вне дерева новая сессия создаётся только продолжением Доктора («Новый Chat»/«Новый Work» в Settings).
- Меню — `popover="auto"` в верхнем слое (не обрезаются списком), позиционируются у кнопки с отступом 8 px от краёв и переворачиваются вверх при нехватке места; закрываются при прокрутке вне меню, resize, открытии другого меню.
- Строка сессии: название (≤2 строки, «Новая сессия» без имени), дата создания (`ru-RU`, день, месяц, время; « · новая» без `chatUrl`), справа read-only badge Chat/Work (Work — акцентный) и `⋯`; выбранная — `aria-current="page"`.
- Видимы максимум 3 строки сессий (`--tree-row-height: 80px`; при ширине панели ≤600/≤430 px — 104/144 px и до 3 строк названия), остальное — прокрутка внутри проекта с видимой полосой 14 px (`scrollbar-gutter: stable`). Прокрутка каждого проекта и общего списка сохраняется между обновлениями; сбрасывается наверх при выборе проекта, создании сессии и появлении новой выбранной сессии (новая — сверху). Дерево перерисовывается только при изменении проектов или выбора.
- Требования доступности: зона раскрытия ≥32 px (кнопка 51 px на всю высоту строки), треугольник ≥11 px (иконка 20 px), `aria-expanded`, без горизонтального переполнения на ширине 312 и 408 px в обеих темах.
- Сверху — только числовая версия `app.getVersion()` и Settings с иконкой 27 px (в 1,5 раза прежней). Нижнего подвала нет. Платформа, сведения о подключении/сессии и стартовая страница находятся в Settings; непривязанные исполнители — в отдельном блоке восстановления.

## Выделение и линии

- Выбранная сессия без маркера-полосы: вся строка (название, дата, badge, `⋯`) в тонкой скруглённой рамке 0.5 px `--tree-guide` на фоне `--tree-selected`, название акцентным цветом; у остальных прозрачная рамка той же толщины, поэтому раскладка не прыгает. Решение пользователя: обводка всей плашки вместо яркой полосы.
- Магистраль соосна chevron (x = 25.5 px), ветви 23.5 px к каждой сессии, последняя ветвь скруглена (6 px). Линии, рамка и chevron — 0.5 px `--tree-guide` = `color-mix(in srgb, var(--tree-accent) 72%, var(--tree-branch))`. Тонкие линии сохраняются по решению пользователя.

## Тема

Settings → «Оформление»: «Светлая»/«Тёмная» (`pilot:set-theme`, `shellTheme`). Тема применяется к сайдбару (`data-theme`, токены `--tree-*` переопределяются для dark), окнам архива и цветов и к нативной панели через `nativeTheme.themeSource` и фон окна (`#f4f6f8`/`#1b1d22`). Настройку темы внутри ChatGPT Web приложение не открывает и не меняет. Других тем нет.

## Индикатор операций

`createProgress`: спиннер, подпись действия и секунды (тик 1 с) в сайдбаре и окне архива. Подпись — по Доктору, проверке/подготовке папки, мастеру, загрузке страницы, ожидающему IPC-действию, рабочей фазе доставки или фоновому прогреву пакета («Подготавливаем контекст заранее»). Скрыт без операции, при ошибке, в Settings/setup и в ожидающих фазах (`waiting-login`, `waiting-draft`, `waiting-composer`, `prepared-stale`, `chat-changed`, `waiting-chat`, `send-unknown`, `error`): ожидание пользователя и завершённая отправка не крутятся. Завершение снимает индикатор и таймер. `prefers-reduced-motion` отключает анимацию.

## Таймер агента

Справа в заголовке карточки «Текущий план проекта» — `mm:ss · Σ mm:ss` (текущее или последнее задание · сумма выбранной сессии), `role="timer"`, без live-анонсов, `aria-label` словами. Пока задание идёт, обновляется локально раз в секунду; пауза (idle в пределах grace) замораживает значение. Источник — `selected.agentRun` и `agentTime` (семантика замера — workspace-sessions).

## Уведомления сессии

- Постоянной карточки контекста нет. Рядом с выбранным проектом показывается только относящаяся к нему ошибка/ожидание/UNKNOWN. Безопасный повтор возможен до Send; unknown/sending дают только наблюдение статуса либо новую сессию. Ни UI, ни старый IPC, ни Доктор не отправляют новый recovery в уже начатый чат. Подробности подключения доступны в Settings.
- Блок проверки проекта в фоне («Проверяем проект в фоне…», ошибка с «Повторить проверку»/«Обновить Workflow Kit» и «Доктор проекта») — см. session-opening-performance.
- Ошибки — баннер `message (code)`. Во время IPC-действия кнопки блокируются; навигационные действия (выбор проекта/сессии, reload, возврат к чату) не блокируют следующий клик.

## Переименование

Свой модальный `<dialog id="rename-dialog">` («Переименовать сессию» / «Переименовать проект», подпись «Название проекта в Web Pilot»), не `window.prompt()` — тот в Electron не показывался. Поле `maxlength=80`, пустое значение не отправляется, Enter сохраняет, Escape/«Отмена» закрывают; ошибка сервера показывается в баннере, диалог остаётся. Правила имён — workspace-sessions.

## Копирование из меню проекта

- «Скопировать полный путь» и «Скопировать строку для внешнего клиента» работают только для зарегистрированного неархивного проекта и пишут лишь в буфер обмена (`await clipboard.writeText`).
- Строка для внешнего клиента (`externalClientLine`, ChatGPT в браузере, Claude, терминальный агент): имя проекта и точная папка JSON-строкой; «прочитай AGENTS.md»; выполнить `./scripts/workflow recover --format text > .harness/runtime/recovery.txt` (Windows `scripts\workflow.cmd recover --format text > .harness\runtime\recovery.txt`) и прочитать файл целиком, частями при необходимости; кратко подтвердить и описать проект и план. Адреса коннектора и ключей в строке нет, в чат ничего не отправляется.

## Геометрия окна и панелей

- Одно `BaseWindow` с `name: 'main-window'` и `windowStatePersistence: { bounds: true, displayMode: false }`: Electron сам сохраняет и восстанавливает позицию и размер и поправляет их при смене дисплеев; maximized/fullscreen не сохраняются (поручение — только позиция и размер). Своего хранилища координат нет. Без сохранённого состояния — 1440×940, минимум 980×700.
- Внутри два `WebContentsView`: сайдбар (x = 0) и ChatGPT справа; `layout()` на каждый resize.
- Ширина сайдбара — `sidebarWidth` в `settings.json`, читается до создания окна. `clampedSidebarWidth()`: сайдбар ≥312 px, ChatGPT ≥600 px. Splitter (`role="separator"`, `aria-valuemin/now`): перетаскивание мышью (запросы объединяются по кадру) и клавиши ←/→ по 24 px; main зажимает значение, перекладывает view и пишет настройку.

## Settings

Панель заменяет дерево: «Доктор проекта» ([project-doctor.md](project-doctor.md)); «Оформление» — тема и «Цвета чата…»; «Интерфейс ChatGPT» — «Скрывать/Показывать» вызовы инструментов (`hideToolCalls`, по умолчанию скрывать, без перезагрузки; поведение фильтра — chatgpt-dom-compatibility); «Локальные инструменты» и «Подключение ChatGPT» (Secure MCP Tunnel / VPS; VPS недоступен, пока свой сервер не готов; детали — [runtime-lifecycle.md](runtime-lifecycle.md)); «Архив…» ([project-archive.md](project-archive.md)). Открытие Settings ничего не ремонтирует; закрытие возвращает к уже загруженной странице без перезагрузки.

**AutoPlan — Chat-сессии (0.6.114).** Поле `#chat-session-task-limit` «Микрозадач на Chat-сессию»: целое **1–10**, по умолчанию **4**, `min/max/step` и подсказка «При включённом AutoPlan… На Work не влияет». Изменение проходит UI-валидацию, preload `setChatSessionTaskLimit` → защищённый `pilot:set-chat-session-task-limit` → `settings.json.chatSessionTaskLimit`; недопустимое значение отклоняется с `role=alert`, ON/OFF не меняется. Настройка общая для приложения, применяется только к sequential Chat с ON; Work/parallel и ручной OFF не ротируются. Достижение лимита показывает ожидание Recovery, ошибка — текст в `#auto-plan-message` с кодом `ROTATION_*` (`role=alert`), кнопка остаётся ON до выбора пользователя. История старого Chat сохраняется ([AutoPlan](auto-plan.md)).

**Восстановление исполнителей.** `snapshot().executorRecovery` — только child без подтверждённого живого parentWorkspace/parentProjectId; в обычном дереве такие записи не появляются. В секции `#executor-recovery` показываются имя, точный путь, причина и отдельная кнопка **«Убрать запись»**; `#executor-recovery-items` обновляется без перезапуска. Кнопка активна лишь в открытых Настройках без pending-операции и передаёт в `webPilot.clearOrphanExecutor({workspace,projectId})` только эти два поля. Main повторно проверяет отсутствующие каталоги/том, pending-журналы (включая `related[]`), busy/UNKNOWN и локальный реестр, затем предлагает нативный диалог с безопасной отменой по умолчанию. Успех удаляет только локальные данные; реальный worktree, браузерный профиль и облачные чаты не трогаются. Отказ и причина видны в баннере; сохранённая запись остаётся доступной для адресного восстановления. Контракт и ошибки — [архив проектов](project-archive.md).

## settings.json

- `<userData>/settings.json`, один писатель: общая последовательная очередь, запись целиком через `settings.json.tmp` (0600) и `rename`, каталог 0700 — без гонок за временный файл.
- Ключи: `chatgptChannel`, `shellTheme` (`light|dark`), `hideToolCalls`, `sidebarWidth`, `chatColors`, `projectsParent`, `projectAutoPlan` (включая `handoff` и отдельные per-Chat DONE checkpoints), `chatSessionTaskLimit`, `reviewCheckpoint`, `automationCheckpoint`, `parallelExecution`, `parallelExecutionBook`; служебные `legacyMacRuntimeRetired`/`legacyWindowsRuntimeRetired`, `legacyRuntimeRoots`; macOS пишет, но не читает `macRuntimeMode: "app-server"` для отката.
- Читается до окна; legacy-отсутствие `chatSessionTaskLimit` означает 4, присутствующее неверное значение не сохраняется молча; нечитаемые настройки дают `SETTINGS_INVALID` в баннере.

## Редактор «Цвета чата»

- Кнопка «Цвета чата…» в Settings (`pilot:open-chat-colors`) открывает одно немодальное перемещаемое окно 440×710 (минимум 400×540, без maximize и меню) со смещением от главного окна; повторное открытие фокусирует/разворачивает существующее. Escape и «Закрыть» закрывают после завершения отправленного изменения.
- Пять nullable цветов `#RRGGBB`: `background` («Фон чата»), `userBackground` («Плашка ваших сообщений»), `userText`, `assistantText`, `composerBackground` («Фон поля ввода»). `null` — штатный вид ChatGPT; в редакторе показываются стандартные значения текущей темы (`DEFAULT_COLORS`) с пометкой «Стандартный»/«Свой цвет».
- Ввод через палитру или HEX применяется сразу (поздние ответы отбрасываются по номеру изменения); сброс одного цвета и общий «сброс» без перезагрузки. Хранение — `settings.json` → `chatColors`; применение и запись идут параллельно, ошибка показывается в редакторе.
- Безопасность: свой preload `webPilotColors` (`getState/change/reset/close/onState`); каналы `chat-colors:*` принимаются только от точного WebContents/mainFrame/URL редактора; навигация и новые окна запрещены; `validateColorChange` отвергает всё, кроме ключа из пяти и `#RRGGBB` (защита от CSS injection). Удалённая страница API не получает.
- Применение (`ChatColors`): одна author-таблица на документ (`insertCSS(…, {cssOrigin:'author'})` + `!important`, потому что user-origin стиль в Electron 44 не снимался `removeInsertedCSS` и ломал сброс), быстрые изменения сводятся к одной таблице, старая снимается после вставки новой, повтор на `dom-ready`/`did-finish-load`/`did-navigate-in-page`, только на `https://chatgpt.com`. Цвета не меняют сообщения, модель, режим, recovery, прокрутку и инструменты; код, ссылки, SVG и кнопки сохраняют цвета. `userBackground` красит только скруглённую плашку сообщения, не строку; `composerBackground` — всю скруглённую плашку поля от «+» до голосовой кнопки; ответ агента окрашивается и во время стриминга.

## Не возвращать

- Маркер-полосу выбранной сессии вместо рамки; толстые линии дерева.
- Ширину сайдбара меньше 312 px; собственное хранилище координат окна; сохранение maximized/fullscreen.
- User-origin CSS для цветов; окраску role-контейнера сообщения пользователя; внешние библиотеки для цветов.
- `window.prompt()` для переименования; индикатор «Контекстное окно» и счётчик токенов (см. workspace-sessions).

- Не проверено: `nativeTheme.themeSource` меняет `prefers-color-scheme` всех WebContents, поэтому при теме ChatGPT «Системная» страница может следовать теме сайдбара. Требование — тему ChatGPT не трогать; настройку ChatGPT приложение действительно не меняет.
- Native Windows: интерфейс на Windows не принят пользователем.
